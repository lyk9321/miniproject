# 11. 카카오톡 커스텀 이모티콘 생성기

> 사용자가 만든 AI 이모티콘을 카카오톡 스타일 채팅 데모에서 GPT 기반 챗봇과 자연스럽게 주고받을 수 있는 웹 서비스

`Python` `OpenAI API` `Streamlit` `NumPy` | 2026.04.09 ~ 04.13 | 팀 프로젝트  
**담당:** 프롬프트 엔지니어링 · OpenAI API 연동 · 카카오톡 채팅 UI 구현

### 구현 목표 및 설계 방향

- 텍스트·이모티콘·사진 세 가지 입력을 하나의 대화 흐름에서 처리하는 멀티모달 챗봇 구현
- 이미지를 대화 기록에 직접 누적하는 대신 Vision API로 텍스트 설명으로 변환 후 기록 → 토큰 효율 + 맥락 유지 동시 확보
- 완성도 판단 기준: 존댓말·긴 답변·AI스러운 표현이 나오면 설계 실패로 간주

### 프롬프트 엔지니어링

단순 지시("친구처럼 말해줘") 대신 8개 섹션으로 구조화된 시스템 프롬프트 설계:

```
① 기본 역할 정의   : 반말, 1~2문장 답변
② 대화 스타일      : ㅋㅋ/ㅎㅎ/ㅠㅠ 자연스럽게, 과한 리액션·반복 표현 금지
③ 입력 해석 방식   : 텍스트·사진·이모티콘 유형별 해석 규칙
④ 사진/이모티콘 대응: 눈에 보이는 내용 우선 반응, 과도한 추측 금지
⑤ 응답 원칙        : 공감 → 짧게 이어가기 → 필요할 때만 질문
⑥ 금지 사항        : 존댓말·3문장 이상·AI 표현·상담사 말투 등 7가지
⑦ 대화 예시        : 실제 카카오톡 대화 예시로 말투·톤 학습 유도
⑧ API 파라미터     : temperature=0.8, max_tokens=100
```

### 멀티모달 처리 파이프라인

```
[텍스트 입력]  → system prompt + 대화 히스토리 + 새 메시지 → GPT-4o-mini
[이모티콘 입력] → PIL 로드 → base64 인코딩
               → Vision API 감정 분석
               → "(이모티콘 전송: 기쁘고 신나는 표정)" 텍스트로 변환
               → 대화 기록에 텍스트로만 저장 → GPT-4o-mini
```

### 트러블슈팅

**단순 프롬프트 사용 시 AI스러운 말투·과한 리액션·반복 표현 문제**  
모델이 지시를 해석하는 방식에 모호함이 원인. 역할·스타일·금지 사항·예시를 8개 섹션으로 명확히 분리하고 실제 카카오톡 대화 예시를 쌍 형태로 추가해 원하는 말투와 톤을 유도. "직전 답변과 비슷한 표현 반복 금지" 등 세부 규칙 추가 후 응답 일관성 크게 향상.

**이미지 대화 기록 누적 시 API 요청 크기 초과 오류**  
이모티콘 이미지를 대화 기록에 직접 누적하면 API 처리 한계 초과. Vision API로 먼저 분석해 짧은 텍스트 설명으로 변환 후 대화 기록에는 텍스트만 저장하는 2단계 파이프라인으로 재설계해 해결.
